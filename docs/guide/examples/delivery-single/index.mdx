## 按列体验

1. 选省份 → 城市、区县、商品、配送方式跟着变，换省会清空下游；
2. 选商品 → 单价自动带出，金额 = 数量 × 单价实时算；
3. 配送方式选「门店自提」→「送达时段」被禁用并清空；
4. 勾「需要发票」→「发票抬头」出现且必填；
5. 数量调大、金额超过 1000 →「备注」变必填；
6. 换商品 →「增值服务」的选项跟着换（生鲜才有保鲜、家电才有上门安装）；
7. 「客户」是 BizSelect：候选来自接口、按省份查，没选省份时点开只提示先选省份；
8. 「手机号」整组校验规则随配送方式替换：快递要 11 位手机号，自提要座机号；
9. 「数量」用自定义 validator：生鲜最多 20 件、家电最多 5 件。

## 页面上的两个开关

| 开关 | 对应配置 | 行为 |
| --- | --- | --- |
| 丢弃草稿不确认 | `confirmDiscard={false}` | 切行 / 取消 / 删除时不再弹「放弃未保存的修改」，直接丢弃 |
| 保存时不校验 | `validateOnSave={false}` | 行内保存放行半成品，由「整表校验」按钮显式把关 |

「整表校验」调的是 `ref.validate()`：逐行跑列上的规则，返回
`{ valid: true, rows }` 或 `{ valid: false, errors }`，失败项只从返回值给出，
怎么提示由页面决定。

## 数据分两层

- `dataSource` 是已确认数据，底部面板实时展示；
- 正在编辑的那一行是组件内部草稿，不在 `dataSource` 里，
  点「读取当前编辑草稿」才看得到。

## 什么时候用 BizSelect，什么时候用 Select

判断标准不是「哪个更强」，而是**候选从哪来**：

- 候选在接口里、要关键词搜索、只有编码时还要还原名称 → `BizSelect`（本页「客户」）；
- 候选是前端常量、或选项由其他字段直接算出来 → antd `Select`（本页「商品」「城市」）。
