# registerField / 字段注册表

字段类型的注册表：`type` → 控件、受控属性名、取值函数、只读渲染、归一化。
它只描述「怎么渲染一个受控控件」，不承担 Form 绑定、校验和联动——那些在
[SchemaFormField](/guide/schema-form-field/)。

## 何时使用

- 业务有自己的控件（行政区选择、富文本、自定义业务组件），希望 schema 里直接用 `type: 'Xxx'`；
- 想覆盖某个内置类型的行为（必须显式 `{ override: true }`）；
- 想给已有控件换受控属性名或补充 `renderRead`。

只是一次性的局部控件：用 `type: 'Custom'`，不要注册全局类型，见
[SchemaField · 自定义字段](/guide/schema-field/#自定义字段typecustom)。

## 快速接入

```tsx
import { registerField } from '@tianyr/schema-antd';
import { InputNumber } from 'antd';

registerField('Money', {
  component: InputNumber,
  // 只读时自定义格式；返回 undefined 会退回内置格式化
  renderRead: (value) => (value == null ? '—' : `¥ ${Number(value).toFixed(2)}`),
});

// schema 里直接写
{ type: 'Money', name: 'amount', label: '金额' }
```

## API

### `registerField(type, definition, options?)`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `type` | `string` | 类型名；`'Custom'` 是保留字，注册会被拒绝并告警 |
| `definition` | `FieldDefinition` | 见下 |
| `options.override` | `boolean` | 已注册时默认拒绝，覆盖必须显式声明 |

### `FieldDefinition`

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `component` | `ComponentType<any>` | 必填 | 受控控件 |
| `valuePropName` | `string` | `'value'` | 受控值属性名（`Checkbox` 用 `checked`，`Upload` 用 `fileList`） |
| `getValueFromEvent` | `(...args) => T` | 取第一个参数 | 从原始事件参数里取出业务值 |
| `renderRead` | `(value, props) => ReactNode` | — | 只读展示；返回 `undefined` 退回内置格式化 |
| `normalize` | `(schema) => schema` | — | 渲染前归一化字段定义；**必须是纯函数且可缓存** |

### 查询

| 函数 | 说明 |
| --- | --- |
| `getFieldDefinition(type)` | 取注册项 |
| `getRegisteredFieldTypes()` | 列出全部已注册类型 |

## 内置类型

```
Input / Input.TextArea / Input.Password / InputNumber
AutoComplete / Cascader / Checkbox / CheckboxGroup / ColorPicker
DatePicker / RadioGroup / Rate / Select / Slider
TimePicker / Transfer / TreeSelect / Upload
```

`BizSelect` / `BizMultiSelect` 由使用方调用 `registerBizSelectField()` 注册，
包本身不产生副作用导入。

## 覆盖内置类型

覆盖是**整条替换，不是合并**：注册表就是 `registry.set(type, definition)`，
新定义里没写的字段会退回默认值（`valuePropName` = `'value'`，`getValueFromEvent`
取第一个参数），不会继承旧注册项。所以覆盖一个带额外行为的类型时，必须把它原有的
行为一起写回来：

| 类型 | 必须一起写回 |
| --- | --- |
| `Checkbox` | `valuePropName: 'checked'`、`getValueFromEvent: (e) => e.target.checked` |
| `Upload` | `valuePropName: 'fileList'`、`getValueFromEvent: (info) => info.fileList` |
| `Transfer` | `valuePropName: 'targetKeys'` |

其余内置类型只登记了 `component`，覆盖时给组件就够了。业务方的浅层封装
（加 `viewMode` 分支、统一尺寸与样式，其余属性照常透传）正好属于这一类：

```ts
import { registerField } from '@tianyr/schema-antd';

// 入口模块里调用一次，放在 App 渲染之前
registerField('Input', { component: BizInput }, { override: true });
registerField('Select', { component: BizSelect }, { override: true });
```

前提是封装层**仍然是受控组件**：接 `value` / `onChange`，其余 props 原样透传。
只要没改值语义，就不必写 `valuePropName` / `getValueFromEvent`；一旦改了取值通道
（内部包了 `Form.Item`、把值包成对象、换了事件形状），就得在封装层边界把值转换回
受控组件的形状，注册项不承担这件事。

## `normalize` 的约定

`normalize` 用来把类型专有属性编译成引擎认识的 shape，典型是
`BizSelect` 的 `paramsFrom` → `dynamic` + `linkage`。

- 必须是纯函数：同样的输入返回相同结构；
- 会按 schema 对象缓存结果，所以**不要返回新对象却不复用输入**的写法；
  每次渲染新建 schema 也会让缓存失效；
- 归一化在 `dynamic` 判断之前执行：类型专有属性可以就地编译出 `dependencies`。

## 注意事项

- **注册是全局的**：注册表是模块级 `Map`，整个应用只有一份。在应用入口
  （或一个启动模块）调用一次即可，不要在每个页面里重复调。
- 重复注册默认被拒绝并告警；HMR 场景显式传 `{ override: true }`。
- `'Custom'` 不能注册：它在 `SchemaField` 里先于注册表分支，由字段自身 `render` 提供。
- 注册项只负责渲染，不负责 `name` / `label` / `rules`。
- 组件拿到的 `props` 已剔除 `value` / `defaultValue` / `onChange`，这些通道由表单接管。
- 未注册的类型：开发态直接抛错，生产态显示「未知字段类型」。
