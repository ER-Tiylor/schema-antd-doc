# BizSelect / BizSelectDisplay

业务下拉组件。它把三件事从页面里收走：

1. **候选从哪来**——静态常量、一次拉全量，还是关键词交给后端；
2. **只有编码时名称怎么回显**——详情页、列表行都能把编码还原成名称；
3. **上级变了旧候选怎么办**——条件变化自动重取，可选自动清空。

值默认存编码，名称由源解析。多选是独立组件，见 [BizMultiSelect](/guide/biz-multi-select/)。

## 快速开始

### 注册数据源（推荐）

注册表解决的是「schema 里写不了函数」：源写在应用启动模块里一次，页面用名字引用。

```ts
// src/config/schema.ts —— 副作用模块，入口 import 一次
import { defineSelectSources, loaded, remote, staticList } from '@tianyr/schema-antd/biz-select';

defineSelectSources({
  province: staticList(PROVINCES),
  currency: loaded(api.listCurrency),
  material: remote({
    recordFields: { value: 'code', label: 'name' },
    search: (keyword, params, signal) => api.pageMaterial({ keyword, ...params }, signal),
    resolve: (code, params) => api.getMaterial(code, params),
    requiredParams: ['warehouseCode'],
  }),
});
```

```ts
// src/main.tsx
import '@/config/schema';
```

#### 页面私有源与 scope

跨页面复用的源不传 scope；页面私有的源传第二个参数，注册名会拼成 `scope:name`，
即使和全局源同名也不会互相覆盖。注册函数返回「短名 → 最终注册名」的映射，
使用点直接用它，不必手写前缀：

```ts
// src/views/pur/sources.ts
export const S = defineSelectSources({ currency, province }, 'pur');
// S = { currency: 'pur:currency', province: 'pur:province' }

// 页面里：直接给组件，或写进 schema
<BizSelect source={S.currency} />;
{ type: 'BizSelect', name: 'provinceCode', source: S.province }
```

- scope 只来自注册入参，**不自动生成、不读路由、不认识 keep-alive**；
- 同一 scope 内短名必须唯一；同名仍然是后注册覆盖（扁平表，不做拒绝）；
- 名字为空、名字含 `:`、scope 含 `:` 或空白会 `console.warn`，仍按原样注册——
  注册发生在启动期，不抛错以免整个应用起不来；
- 不传 scope 就是原来的全局注册，老代码零改动。

### 组件

组件是**受控**的：`value` 由外部决定，必须配 `onChange`。

```tsx
import { BizSelect } from '@tianyr/schema-antd/biz-select';

<BizSelect
  source="material"
  params={{ warehouseCode }}
  value={materialCode}
  onChange={(next) => setMaterialCode(next)}
/>;
```

放进 `Form.Item` 时由表单注入 `value` / `onChange`，不用自己写。

### schema

```ts
import { registerBizSelectField } from '@tianyr/schema-antd/biz-select';

registerBizSelectField(); // 使用方显式注册，包默认不注册
```

```ts
const schema = [
  { type: 'BizSelect', name: 'warehouseCode', label: '仓库', source: 'warehouse' },
  {
    type: 'BizSelect',
    name: 'materialCode',
    label: '物料',
    source: 'material',
    paramsFrom: { warehouseCode: 'warehouseCode' },

  },

```

### 不注册也能用

注册只影响「能不能用名字引用」，组件本来就可以直接吃源对象：

```tsx
<BizSelect options={STATUS} value={v} onChange={setV} />
<BizSelect source={loaded(api.listCurrency)} value={v} onChange={setV} />
<BizSelect source={{ load: api.listCurrency }} value={v} onChange={setV} />
```

内联**箭头函数**每次渲染都是新源，缓存会一直失效（开发态有告警）。要跨实例共享就把函数提到模块外，或给源一个 `cacheKey`。

## 概念

### 选项契约：`BizOption`

组件只认 `{ value, label }`，与 antd 同词汇：

```ts
interface BizOption<T = unknown> {
  value: string | number;
  label?: string;
  disabled?: boolean;
  /** 源返回的原始记录，原样带回 onChange 第二个参数 */
  raw?: T;
}
```

后端返回 `{ code, name }`、`{ tenantUserId, tenantUserName }` 都很正常，那是**数据入口的方言**，在源的 `recordFields` 上映射一次，下游只认契约形状。

### 源：`SelectSource`

源只声明**能力**，不声明类型，不认识 URL、method、接口名：

```ts
interface SelectSource<P extends SelectParams = SelectParams> {
  /** 同步全集：纯前端常量 */
  options?: BizOption[];
  /** 异步全集：一次拉完，之后前端过滤 */
  load?: (params: P, signal?: AbortSignal) => Promise<Array<BizOption | object>>;
  /** 关键词搜索：过滤在后端 */
  search?: (keyword: string, params: P, signal?: AbortSignal) => Promise<Array<BizOption | object>>;
  /** 按值精确回显 */
  resolve?: (value: SelectValue, params: P, signal?: AbortSignal) => Promise<BizOption | object | null>;
  /** 按值批量回显：接口支持 IN 查询时才有意义 */
  resolveMany?: (values: SelectValue[], params: P, signal?: AbortSignal) => Promise<Array<BizOption | object>>;
  /** 缺任一参数就不发请求 */
  requiredParams?: string[];
  /** 租户 / 权限隔离，参与缓存键 */
  namespace?: () => string;
}
```

### 能力 → 行为

不需要选「类型」，提供什么能力就走什么行为：

| 提供的能力 | 候选模式 | 展开下拉时 | 输入关键词时 | 回显方式 |
| --- | --- | --- | --- | --- |
| `options` | 同步全集 | 不请求 | 前端过滤 | `options` 里查 |
| `load` | 异步全集 | 拉一次全量 | 前端过滤 | 全集里查（必要时提前拉） |
| `search` | 后端搜索 | 用空关键词取默认候选 | 防抖后交后端 | 依赖 `resolve` |
| `load` + `search` | 混合 | 拉全量 | 有关键词走后端，清空回到全集 | 全集或 `resolve` |
| 只有 `resolve` / `resolveMany` | 无候选 | 空 | 空 | 按值解析 |

没有 `load` 也没有 `search` 时，组件只能当只读展示用；`options` 和 `load` 同时给时 `options` 优先。

### `recordFields` 和 `valueFields` 是两条通道

| 属性 | 声明在哪 | 管什么 | 例子 |
| --- | --- | --- | --- |
| `recordFields` | 源工厂的配置 | **接口记录怎么读** | 返回 `{ userId, userName }` → `{ value: 'userId', label: 'userName' }` |
| `valueFields` | 组件 / schema | **值对象怎么存** | 存成 `{ userId, userName }` → `{ value: 'userId', label: 'userName' }` |

一个在取数时把方言翻成契约，一个在存储时决定对象的键名。形状相同，但方向不同，不要混用。

### 值与展示

```ts
valueMode: 'primitive'; // 默认：value 是编码 string | number
valueMode: 'object'; // value 是对象，键名由 valueFields 决定
displayMode: 'L' | 'V' | 'V-L'; // 显示名称 / 编码 / 编码-名称
```

`displayMode` 同时决定默认的前端过滤字段：`V` → 编码，`V-L` → 两者，`L` → 名称。要覆盖就传 `searchFields`。

## 数据源契约（逐项说明）

### `options`

```ts
options?: BizOption[];
```

同步全集。没有请求、没有 loading，候选直接来自这里。字典、状态枚举、省份这类固定数据用它。

> `staticList()` 没有 `recordFields` 时**整个对象原样就是选项**，附加字段不会被搬进 `raw`，调用方在 `onChange` 上仍能直接读到。

### `load(params, signal?)`

```ts
load: (params: SelectParams, signal?: AbortSignal) => Promise<Array<BizOption | object>>;
```

- **什么时候调用**：展开下拉时拉一次；`BizSelect` 在「有值但没有已知名称」时会为了回显提前拉一次（`load` 型没有 `resolve`，名称只能从全集里找）。已有名称（对象值或 `seedOptions` 命中）不会多拉。
- **返回什么**：对象数组，元素是后端原始记录。声明了 `recordFields` 就按声明映射，原始记录进 `raw`；没声明就当作已经是 `{ value, label }`。
- **一次就够**：拉完之后关键词只在前端过滤，不会再发请求。
- **`params`**：就是组件 `params` prop 原样传进来的对象，见下文「`params` 从哪来」。
- **`signal`**：当前调用处传的是 `undefined`，取消靠内部序号作废旧结果；写了 `signal` 也不会报错，但不要依赖它做取消。

```ts
const currencySource = loaded(
  (params) => api.listCurrency({ enabled: 1, ...params }),
  { recordFields: { value: 'currencyCode', label: 'currencyName' } },
);
```

### `search(keyword, params, signal?)`

```ts
search: (
  keyword: string,
  params: SelectParams,
  signal?: AbortSignal,
) => Promise<Array<BizOption | object>>;
```

- **什么时候调用**：
  - 输入关键词后，防抖 `debounceMs`（默认 300ms）发一次；
  - 纯搜索型（没有 `load`）第一次展开下拉时，会用**空关键词**调一次，拿默认候选；
  - 条件变化且下拉还开着时，会清掉关键词重新用空关键词查一次。
- **空关键词**：必须返回可用的默认候选。原 `SearchInput` 里空关键词走的是另一个不带搜索字段的请求，迁移时注意别把 `keyword: ''` 拼进去。
- **返回什么**：同 `load`。候选范围完全由后端决定，组件不会再做前端二次过滤。
- **`signal`**：会收到真实的 `AbortSignal`，但**取消的正确性靠内部序号**——即使源不认 `signal`、请求照样返回，旧结果也会被丢弃。
- **报错**：`throw` / `reject` 即可。下拉里会显示「加载失败，点击重试」，失败不进缓存。

```ts
search: async (keyword, params, signal) => {
  const res = await api.pageMaterial({ ...params, keyword: keyword || undefined }, { signal });
  return res.list; // 接口包了一层就自己解包
};
```

### `resolve(value, params, signal?)`

```ts
resolve: (
  value: SelectValue,
  params: SelectParams,
  signal?: AbortSignal,
) => Promise<BizOption | object | null>;
```

- **什么时候调用**：有值、本地（对象值 / `seedOptions` / 已加载候选）找不到名称时，按值精确查一次。
- **用途只能是精确回显**：不要用模糊搜索接口冒充。返回的记录编码必须和传入的 `value` 一致，不一致会被丢弃（认错比认不出更糟）。
- **返回 `null`**：表示记录不存在，组件显示原始编码，状态记为 `missing`。
- **`params`**：与候选用同一份条件；缺 `requiredParams` 时不发请求。
- **缓存**：按「租户 + 来源 + 编码 + 参数」缓存，查到 5 分钟、查不到 30 秒。

### `resolveMany(values, params, signal?)`

```ts
resolveMany: (
  values: SelectValue[],
  params: SelectParams,
  signal?: AbortSignal,
) => Promise<Array<BizOption | object>>;
```

只有接口真的支持 IN 过滤时才声明——参数名对不上、或有返回条数上限都不算支持。声明了却查不全，会被当成「记录不存在」显示编码。

多选、表格列批量回显会优先用它；只声明 `resolveMany` 也能单条解析（批量一条就是单条），不必再写一个 `resolve`。

### `requiredParams`

```ts
requiredParams?: string[];
```

这些键在 `params` 里必须都有值（`undefined` / `null` / `''` / 空数组都算缺）：

- 缺任何一个 → 组件禁用、候选为空、**一个请求都不发**，占位文案换成 `blockedText`；
- `resolve` 同样被挡住，只读态显示原始编码并在 `title` 上说明原因。

用空条件查可能拿到别家数据，所以宁可不查。

### `namespace`

```ts
namespace?: () => string;
```

租户 / 权限的**缓存作用域**，参与缓存键，不是注册表命名空间。切换租户后旧候选不会被当成当前结果。

### `params` 从哪来

源的三个函数拿到的 `params` 是**同一个对象**，来源只有两条：

| 使用方式 | 来源 |
| --- | --- |
| 组件 | `params` prop 原样传入 |
| schema | `props.params`（静态）和 `paramsFrom` 映射合并后的结果 |

schema 的合并优先级：`props.params` < `dynamic.props().params` < `paramsFrom` 映射。`params` 参与缓存键；值一变，在途请求作废，自动重新取数——不需要像 `SearchInput` 那样写 `key={xxx}` 强制重挂载。

> 源函数形参不要也叫 `params`，容易和组件 prop 混淆。建议写 `search: (keyword, query) => ...`。

### 返回值的处理规则

```ts
// 库做的唯一一步：可选字段映射
declare recordFields: { value?: string; label?: string };
```

- 声明 `recordFields` → 按声明取两个字段，`label` 统一转字符串，原始记录放进 `raw`；
- 没声明 → 元素原样使用，必须已经是 `{ value, label }`；
- **不做**：`code → value` 自动嗅探、`res.list` 解包、`code/name` 兜底。这些都在源函数里自己做。

```ts
// 典型写法：解包 + 拼搜索条件
const pageMaterial = async (query: Record<string, unknown>, signal?: AbortSignal) => {
  const res = await api.pageMaterial(query, { signal });
  return Array.isArray(res) ? res : (res?.list ?? []);
};
```

## 源工厂

三个工厂只做形状收敛：不注册、不缓存、不发请求。

### `staticList(list, recordFields?)`

```ts
function staticList(
  list: ReadonlyArray<BizOption | object>,
  recordFields?: { value?: string; label?: string },
): SelectSource;
```

前端常量。传 `recordFields` 时会把记录映射成契约形状并把原记录放进 `raw`；不传则原样使用。

```tsx
// 已经是契约形状
const STATUS = [
  { value: 'enabled', label: '启用' },
  { value: 'disabled', label: '停用' },
];
<BizSelect options={STATUS} ... />

// 后端方言，加一次映射
const PAY_TYPE = staticList(PAY_TYPES, { value: 'code', label: 'name' });
```

数据字典本身就是 `{ value, label }`（还可能带 `resValue` 之类附加字段），直接 `staticList` 整条带过去，附加字段在 `onChange` 第二个参数上仍然能读到；换 `loaded` + `recordFields` 反而会把它们挪进 `raw`。

### `loaded(load, options?)`

```ts
interface LoadedOptions {
  recordFields?: { value?: string; label?: string };
  requiredParams?: string[];
  namespace?: () => string;
}

function loaded<P extends SelectParams>(
  load: (params: P, signal?: AbortSignal) => Promise<Array<BizOption | object>>,
  options?: LoadedOptions,
): SelectSource<P>;
```

有限远程枚举：一次拉全量，之后前端过滤。

```ts
export const currencySource = loaded(
  (params) => api.listCurrency({ enabled: 1, ...params }),
  { recordFields: { value: 'currencyCode', label: 'currencyName' } },
);
```

注意：

- 一定要传**模块级函数**（`api.listCurrency`）或 `useMemo` 后的源；内联箭头每次渲染换身份，缓存失效；
- 展开下拉才拉数据；编辑态有值时为了回显会提前拉一次；
- 关键词不会发给后端。

### `remote(config)`

```ts
interface RemoteOptions {
  search: (keyword: string, params: SelectParams, signal?: AbortSignal) => Promise<Array<BizOption | object>>;
  resolve?: (value: SelectValue, params: SelectParams, signal?: AbortSignal) => Promise<BizOption | object | null>;
  resolveMany?: (values: SelectValue[], params: SelectParams, signal?: AbortSignal) => Promise<Array<BizOption | object>>;
  recordFields?: { value?: string; label?: string };
  requiredParams?: string[];
  namespace?: () => string;
}

function remote(config: RemoteOptions): SelectSource;
```

无限远程：关键词交给后端，按值精确回显。

```ts
export const materialSource = remote({
  recordFields: { value: 'id', label: 'name' },
  search: async (keyword, query) => {
    const res = await api.pageMaterial({ ...query, keyword: keyword || undefined });
    return res.list;
  },
  resolve: (id, query) => api.getMaterial(id, query),
  resolveMany: (ids, query) => api.materialDropDown({ ids, ...query }),
  requiredParams: ['warehouseCode'],
});
```

注意：

- **只有 `search` 没有 `load`** 时，展开下拉会用空关键词取一次默认候选；不声明 `resolve` 的话，详情 / 编辑态只能靠候选或 `seedOptions` 显示名称，拿不到就退化成编码；
- 搜索结果不做前端二次过滤；
- `resolve` 必须精确查，不能拿搜索接口代用。

### 需要 `load` + `search` 时

三个工厂覆盖不了这个组合，直接写内联源：

```ts
const toOption = (row: Material): BizOption => ({ value: row.id, label: row.name, raw: row });

const hybridSource: SelectSource = {
  load: async (params) => (await api.listMaterial(params)).map(toOption),
  search: async (keyword, params) => (await api.pageMaterial({ keyword, ...params })).list.map(toOption),
  resolve: async (id, params) => toOption(await api.getMaterial(id, params)),
  requiredParams: ['warehouseCode'],
};
```

内联源没有 `recordFields`，映射在函数里做。要跨实例共享缓存，把源提到模块外并传导入函数，或显式 `cacheKey`。

### 注册源 vs 内联源

| | 注册源 | 内联源 |
| --- | --- | --- |
| 写法 | `source="material"` | `source={materialSource}` |
| schema 可用 | ✅ | ❌（schema 装不下函数） |
| 缓存身份 | 注册名 + 版本号 | `cacheKey` / 内容 / 函数引用 |
| 失效 | `invalidateSelectSource(name)` | 换 `cacheKey` 或依赖源身份变化 |

## 组件 API

### `BizSelectProps`

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `source` | `string \| SelectSource` | — | 注册名或内联源 |
| `options` | `BizOption[]` | — | 静态候选简写，等价 `source={{ options }}`；与 `source` 同给时以 `source` 为准 |
| `params` | `Record<string, unknown>` | — | 传给 `load` / `search` / `resolve`，参与缓存键 |
| `value` | `SelectValue \| BizObjectValue` | — | `primitive` 是编码；`object` 是对象 |
| `onChange` | `(value, option?: BizOption) => void` | — | 清空时为 `undefined`；`option.raw` 是原始记录 |
| `valueMode` | `'primitive' \| 'object'` | `'primitive'` | 值形态 |
| `valueFields` | `{ value?: string; label?: string }` | `{ value: 'value', label: 'label' }` | 对象值里哪个键装值 / 名称 |
| `displayMode` | `'L' \| 'V' \| 'V-L'` | `'L'` | 显示名称 / 编码 / 编码-名称 |
| `searchFields` | `'value' \| 'label' \| 'both'` | 随 `displayMode` | 前端过滤匹配哪些字段 |
| `seedOptions` | `BizOption[]` | — | 页面已知候选，省一次 `resolve` |
| `debounceMs` | `number` | `300` | 远程搜索防抖 |
| `cacheKey` | `string` | — | 内联源跨实例共享缓存；注册名自带稳定键，再传不生效 |
| `blockedText` | `ReactNode` | `'请先选择上级'` | 缺 `requiredParams` 时的占位与下拉提示 |
| `disabled` / `placeholder` / `allowClear` / `clearIcon` / `style` / `popupMatchSelectWidth` / `optionRender` … | antd `SelectProps` | — | 其余透传 |

### 受控与清空

- `value` 恒由外部决定，没有 `defaultValue`；
- 清空就是一次普通值变更：`onChange(undefined, undefined)`，`required` 校验、联动、`events` 照常触发；
- `allowClear` 默认**没有**清除按钮（antd 透传），要就显式写；`clearIcon` 同样透传；
- 受控通道和搜索协议被组件接管，以下属性传了无效：
  `value` / `defaultValue` / `onChange` / `labelInValue` / `mode` /
  `onSearch` / `searchValue` / `showSearch` / `filterOption` / `optionFilterProp` / `optionLabelProp`；
- `options` 不是 antd 原始选项的透传通道，而是静态候选简写；额外字段要带到回调里，
  用 `staticList(rows, recordFields)` 或自己塞 `raw`。

### `onChange` 的第二个参数

```ts
onChange(value, option);
// option: { value, label?, disabled?, raw? }
```

- `raw` 是源给的原始记录：声明了 `recordFields` 时，它就是后端那一行；
- 对象值形态只回写 `valueFields` 指定的两个键，需要更多字段从 `option.raw` 取；
- 清空时第二个参数也是 `undefined`，不要在回调里无条件解构。

### `BizSelectDisplayProps`

只读展示，复用同一套名称解析，但不挂载 `Select`。

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `source` / `options` / `params` / `seedOptions` / `cacheKey` | 同 `BizSelect` | — | |
| `value` / `valueMode` / `valueFields` / `displayMode` | 同 `BizSelect` | — | |
| `emptyText` | `ReactNode` | `'—'` | 空值占位 |

解析状态（`loading` / `missing` / `blocked` / `error`）挂在 `title` 上；**查不到名称就显示原始编码，不会编一个名称**。

## 场景示例

### 静态枚举

```tsx
const LEVELS = [
  { value: 1, label: '一级' },
  { value: 2, label: '二级' },
];

<BizSelect options={LEVELS} value={level} onChange={setLevel} allowClear />;
```

### 数据字典

```tsx
const { dictData: [SHUILV] } = useDataDict(['shuilv'], companyId);
const source = useMemo(() => staticList(SHUILV ?? []), [SHUILV]);

<BizSelect source={source} value={taxCode} onChange={(next) => setTaxCode(String(next ?? ''))} />;
```

`useMemo` 的依赖必须带字典数组本身：字典通常按租户过滤，换了租户没重算会拿到上一家的。

### 有限枚举 + 字段映射

```ts
const currencySource = loaded(api.listCurrency, {
  recordFields: { value: 'currencyCode', label: 'currencyName' },
});
```

```tsx
<BizSelect source={currencySource} value={currency} onChange={setCurrency} />
```

### 远程搜索 + 精确回显

```ts
const customerSource = remote({
  requiredParams: ['orgId'],
  recordFields: { value: 'id', label: 'customerName' },
  search: async (keyword, query) => {
    const res = await api.pageCustomer({ ...query, keyword: keyword || undefined });
    return res.list;
  },
  resolve: (id, query) => api.getCustomer(id, query),
});
```

```tsx
<BizSelect
  source={customerSource}
  params={{ orgId }}
  value={customerId}
  onChange={setCustomerId}
  blockedText="请先选择组织"
  allowClear
/>
```

### 级联条件

```tsx
<BizSelect
  source="city"
  params={{ provinceCode }}
  value={cityCode}
  onChange={setCityCode}
  blockedText="请先选择省份"
/>
```

父字段变化 → `params` 变 → 在途请求作废，展开时按新条件取数。schema 里用 `paramsFrom` 还会顺手清空本字段。

### 详情回显：`seedOptions`

详情接口已经带回了名称所在的那条记录，直接给组件，省一次 `resolve`：

```tsx
const seedOptions = detail?.warehouse
  ? [{ value: detail.warehouse.id, label: detail.warehouse.name }]
  : [];

<BizSelect source="warehouse" seedOptions={seedOptions} value={detail?.warehouseId} onChange={...} />;
```

`seedOptions` 只是候选，不改变值；命中后不再请求。

### 对象值

后端要求提交 `{ value, label }` 或多组键名时：

```tsx
<BizSelect
  source="material"
  valueMode="object"
  valueFields={{ value: 'materialId', label: 'materialName' }}
  value={material}
  onChange={setMaterial}
/>
```

值形如 `{ materialId: 'm1', materialName: '螺丝' }`。注意对象里**只有这两个键**，其他字段从 `option.raw` 取。

### 只读

```tsx
<BizSelectDisplay source="material" value={row.materialId} params={{ warehouseCode: row.warehouseCode }} />
```

### schema + `paramsFrom`

```ts
{
  type: 'BizSelect',
  name: 'userId',
  label: '负责人',
  source: 'user',
  paramsFrom: {
    orgId: 'orgId',                      // 字段值原样当参数
    userId: { from: 'owner', pick: 'id' }, // 父值是对象时取其中一个键
  },
  clearOnParent: true,                   // 默认 true
}
```

- 合并优先级：`props.params` < `dynamic.props().params` < `paramsFrom` 映射；
- `pick` 取不到给 `undefined`，交给 `requiredParams` 挡请求，不会退回整个对象；
- `clearOnParent: false` 用于快照语义（父变不清空）。

## 行为细节

### 加载时机

| 场景 | 是否请求 |
| --- | --- |
| 挂载但未展开、没有值 | 不请求 |
| 挂载、有值、源是 `load` 型且没有已知名称 | 为回显拉一次全集 |
| 展开下拉 | `load` 型拉全集；纯 `search` 型用空关键词查一次 |
| 输入关键词 | `search` / 混合型防抖后请求；`load` 型只前端过滤 |
| `params` 变化 | 作废旧请求；下拉开着且是纯 `search` 型时立即重查，其余等下次展开 |
| 清空选中值 | 不额外请求 |

### 回显优先级

```
对象值自带的名称 → seedOptions → 已加载候选 → resolve(value)
→ 最近一次命中过的选项 → 原始编码
```

- 最后一档是给搜索型源兜底的：候选会随关键词整批换掉，已选项常常不在里面；
- `resolve` 返回的编码与传入值不一致会丢弃；
- 查不到时只显示编码，状态在只读态挂在 `title` 上（`missing` / `blocked` / `error`）。

### 缓存

| 缓存 | 键 | 有效期 |
| --- | --- | --- |
| 候选集 | `租户 ｜ 来源键 ｜ 参数键` | 有结果 5 分钟 / 空结果 30 秒 |
| 单条解析 | `租户 ｜ 来源键 ｜ 编码 ｜ 参数键` | 同上 |
| 在途请求 | 同上 | 同键共享一次；失败不缓存 |

来源键（身份）四档，从强到弱：

| 写法 | 身份 | 跨实例共享 |
| --- | --- | --- |
| `source="city"` | 注册名 + 版本号 | ✅ |
| `source={{ options: [...] }}` | 内容哈希 | ✅ |
| `source={{ load: api.list }}` | 函数引用 | ✅ |
| `source={{ load: () => api.list() }}` | 每渲染都变 | ❌ |

`invalidateSelectSource(name)` 把版本号 +1，已挂载实例换 key：`load` 型已取过数的会重取，纯搜索型等下次展开。

### 错误与重试

- `load` / `search` 失败：下拉显示「加载失败，点击重试」，失败不进缓存；
- `resolve` 失败：只读态显示编码，`title` 说明「名称解析失败」；
- 组件不会自动重试，避免故障时放大请求。

### 已选项补回候选

非搜索态下，如果已选项不在当前候选里，会补一条，否则选中值在下拉里显示为空。搜索中不补（避免混进不匹配的记录），取数失败时也不补（否则重试入口被藏起来）。

## 常见错误

| 写法 | 问题 | 改法 |
| --- | --- | --- |
| `source={{ load: () => api.list() }}` | 每次渲染新函数，缓存失效，100 行表格 = 100 次请求 | 传导入函数或模块级源；或给 `cacheKey` |
| 后端返回 `{ code, name }`，源没写 `recordFields` | 选项 `value` 为 `undefined`，下拉一片空白 | 显式声明映射，不做自动嗅探 |
| `recordFields` 和 `valueFields` 混用 | 一个是读接口，一个是存对象 | 按上文两条通道分开 |
| `resolve` 接模糊搜索接口 | 可能返回别的记录，名称错位 | 用按 ID 精确查的接口 |
| `requiredParams: ['orgId']` 但 `params` 里叫 `orgID` | 永远 `blocked`，不发请求 | 参数名逐字对齐 |
| `paramsFrom: { userId: 'user' }` 而 `user` 是对象 | 整个对象当参数发出去，后端静默出错 | 用 `{ from: 'user', pick: 'id' }`，或直接映射 `user.id` |
| 期望默认有清除按钮 | antd 需要 `allowClear` | 显式传 `allowClear` |
| 在 `onChange` 里读 `option.raw.xxx`，源又是纯 `options` | 没有映射时 `raw` 为空 | 用 `staticList(rows, recordFields)` 或自己在源里带 `raw` |
| 给 `BizSelect` 传 `mode="multiple"` | 属性被 omit，不生效 | 换 [BizMultiSelect](/guide/biz-multi-select/) |
| 搜索型源期望「输入时前端过滤」 | 过滤在后端 | 前端过滤型用 `load` / `options` |
| 两个页面各注册一个 `province`，含义不同 | 扁平表，后注册的覆盖前者，已挂载实例跟着换源 | 页面私有源传 scope：`defineSelectSources({ province }, 'pur')`，使用点接返回值 `S.province` |

## 与 `SearchInput` 的对应关系

迁移时最常对照的几项：

| `SearchInput` | `BizSelect` |
| --- | --- |
| `url` + `requestMethod` | 源函数里自己发请求 |
| `params` | `params` prop（变化自动重取，不再需要 `key`） |
| `other.key` / `labelName` | `recordFields` |
| `other.searchName` | 在 `search` 里拼搜索参数名 |
| `option.data.xxx` | `option.raw?.xxx` |
| `rest.labelInValue` | `valueMode='object'` |
| `rest.mode='multiple'` | `BizMultiSelect` |
| `viewMode` | `BizSelectDisplay` |
| `initialOptions` | `seedOptions` |
| 强制 `allowClear` | 需显式传 `allowClear` |

## 当前不支持

| 不支持 | 说明 |
| --- | --- |
| `mode="tags"` | 值是源里的实体，不是用户输入的字符串 |
| `labelInValue` | 与受控通道冲突，标签由 `displayMode` 决定 |
| 分组 / 树形选项 | 契约是扁平 `{ value, label }`，`children` 会被忽略 |
| 自动识别后端字段名 | 故意不做，显式声明 `recordFields` |
| `{value,label}` ↔ 平铺 `xxId/xxName` 自动转换 | 属表单边界，用 [defineFlatFields](/guide/define-flat-fields/) |
| `onSearch` 回传关键词 | 搜索行为由源占用 |
| `V-L` 自定义分隔符 | 固定 `-`，要换就在渲染层自己拼 |
